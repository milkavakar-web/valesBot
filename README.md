# Свой торговый бот для Binance

Простой бот с веб-панелью: спот и фьючерсы USDⓈ-M, вход по RSI или пересечению EMA,
усреднения, тейк-профит, стоп-лосс и проверка стратегии на истории. Без подписок и
процента с прибыли — работает на вашем компьютере или сервере.

## Запуск на любом компьютере

Во всех способах запускается одно и то же. Рядом с программой при первом запуске
появятся файл настроек `.env` (ключи Binance и Telegram) и папка `data/` (боты и
сделки). Панель сама откроется в браузере. Если порт 8000 занят, она встанет на
следующий свободный; если бот уже запущен, просто откроется панель. Остановить бота
можно, закрыв окно или нажав Ctrl+C. Позиции и стопы на бирже при этом остаются, а
при следующем запуске боты продолжат работу.

**Windows**

- **Готовый файл.** Скачайте `ValesBot-windows.exe` со страницы Releases репозитория,
  положите его в отдельную папку и запустите двойным щелчком. Python не нужен. Windows
  может предупредить о «неизвестном издателе»: «Подробнее» → «Выполнить в любом случае».
- **Из исходников.** На GitHub нажмите Code → Download ZIP (или `git clone`), распакуйте
  и запустите `start.bat` двойным щелчком. При первом запуске скрипт поставит uv —
  небольшую утилиту, которая сама скачает Python и библиотеки, без прав администратора.
  Это займёт минуту-две, следующие запуски — секунды.

**macOS**

- **Готовый файл** `ValesBot-macos` из Releases (для Mac на Apple Silicon). Первый раз
  откройте его через правый клик → «Открыть», иначе macOS его не пустит. Или выполните
  в терминале `xattr -d com.apple.quarantine ValesBot-macos`.
- **Из исходников:** двойной щелчок по `ValesBot.command` или `./start.sh` в терминале.

**Linux**

- `./start.sh`. Если в системе есть Python 3.10 или новее с venv, скрипт поставит
  библиотеки в папку `.venv`. Если нет — сам скачает uv и Python, sudo не нужен.
- Или готовый `ValesBot-linux` из Releases.

**Сервер** — Docker, см. раздел «Запуск на сервере» ниже.

**Обновление.** Из исходников — `git pull` или новый ZIP поверх старого. Готовый файл —
просто замените его новым. `.env` и `data/` не трогайте: в них настройки, боты и сделки.

Готовые файлы собирает GitHub Actions (`.github/workflows/build.yml`), когда в репозиторий
отправляют тег версии, например `v0.1.0`. Собрать вручную на своей системе:

```bash
pip install -r requirements.txt pyinstaller && pyinstaller valesbot.spec
```

## Три режима — проходите их по порядку

1. **Бумажная торговля.** Бот берёт настоящие цены Binance, но сделки только
   записывает. Комиссии учитываются (0,1% спот, 0,05% фьючерсы). Погоняйте так
   хотя бы неделю.
2. **Демо-счёт Binance.** Настоящие ордера, но на тестовые деньги. Зайдите на
   https://demo.binance.com, создайте ключ API в разделе API Management и впишите его
   в `BINANCE_DEMO_API_KEY` и `BINANCE_DEMO_API_SECRET` в `.env`. Здесь проверяется,
   что ордера реально проходят: минимальные суммы, точность объёма, плечо.
3. **Реальные деньги.** Впишите `BINANCE_API_KEY` и `BINANCE_API_SECRET`, поставьте
   `ALLOW_LIVE=1` и перезапустите программу. Начните с минимальных сумм.

После правки `.env` программу нужно перезапустить.

## Ключ API: как сделать безопасно

- Права: чтение и спотовая торговля, для фьючерсов ещё «Enable Futures».
- **Вывод средств не включайте никогда.** Тогда даже украденный ключ не позволит
  забрать деньги со счёта.
- Привяжите ключ к IP вашего сервера (Restrict access to trusted IPs).
- Ключи хранятся только в файле `.env` на вашей машине, в интерфейс и базу они не попадают.

## Конструктор условий

Сигнал собирается в редакторе бота из строк вида «индикатор — условие — значение»,
например «RSI(14) ниже 30» и «цена выше EMA(200)». Строки внутри набора соединяются
через «и»: сигнал срабатывает, когда выполнены все.

- **Индикаторы:** цена, RSI, EMA, SMA, полосы Боллинджера (верхняя, средняя, нижняя),
  MACD (линия, сигнальная, гистограмма), стохастик (%K, %D), изменение цены за N свечей
  в %, объём и объём к среднему за N свечей (2 — вдвое больше обычного).
- **Условия:** «выше», «ниже», «пересекает снизу вверх», «пересекает сверху вниз».
  Справа — число или другой индикатор.
- **Наборы:** вход в лонг, вход в шорт, выход из лонга, выход из шорта. Видны только
  наборы для выбранного направления; шорт и «Оба» — только на фьючерсах.
- **Выход:** позицию закрывает то, что сработает первым — тейк-профит, стоп-лосс или
  условия выхода. При направлении «Оба» можно включить разворот: сигнал в другую
  сторону закрывает позицию и открывает обратную.
- Режим «Сразу, без условий» входит сразу после закрытия предыдущей сделки.

Условия проверяются на закрытии каждой свечи, вход — по цене открытия следующей.
Проверка на истории и график используют те же условия автоматически, а в причине
каждой сделки видны значения индикаторов: «RSI(14) 28,5 ниже 30 и цена 76 684 выше
EMA(200) 76 099».

Чтобы добавить свой индикатор, опишите его в `CATALOG` и посчитайте в `_calc()` в
`app/rules.py` — в панели он появится сам.

## Шаблоны

| Шаблон | Тип | Как работает |
|---|---|---|
| DCA: усреднение по RSI | DCA | RSI(14) ниже 35, 5 усреднений, тейк 1,2% |
| DCA только в восходящем тренде | DCA | то же, но только когда цена выше EMA(200) |
| Тренд: пересечение EMA 20 и 50 | тренд | вход и выход по пересечениям, стоп 5% |
| Тренд: пробой Боллинджера на объёме | пробой | цена выше верхней полосы при объёме ×1,5, выход у средней |
| Отскок RSI по тренду | откат | RSI ниже 30 при цене выше EMA(200), выход при RSI выше 60 |
| Боковик: от нижней полосы к средней | боковик | вход от нижней полосы Боллинджера, выход у средней |
| MACD: разворот ниже нуля | разворот | MACD пересекает сигнальную снизу вверх ниже нуля |
| Стохастик из перепроданности | откат | %K пересекает %D ниже 20, выход при %K выше 80 |
| Тренд в обе стороны (фьючерсы) | тренд | EMA 20/50: лонг и шорт с разворотом |

DCA даёт очень много плюсовых сделок, но прибыль мелкая, а риск скрытый: при долгом
падении в позиции застревает весь депозит. На споте без плеча в худшем случае вы просто
держите монету; на фьючерсах с плечом так можно дойти до ликвидации. Трендовые шаблоны
чаще закрываются в минус, но редкие большие движения перекрывают серии мелких убытков.

Сетка (грид) и арбитраж фандинга условиями не описываются: сетке нужны десятки
отдельных ордеров по уровням цены, арбитражу — одновременно спот, шорт на фьючерсах и
данные о фандинге. Это отдельные движки. Сеточные и DCA-боты бесплатно есть у самого
Binance в разделе Trading Bots — там платите только обычную комиссию биржи.

Советы:

- Для начала берите BTC/USDT или ETH/USDT, свечи 15m или 1h. На 1m много шума и комиссий.
- На фьючерсах начинайте с плеча 1–2 и всегда ставьте стоп-лосс.
- Проверяйте стратегию на разных периодах. Если она прибыльна только на одном — это
  подгонка, а не преимущество.

## Проверка на истории и график

Кнопка «Проверить на истории» есть в редакторе бота (проверяет настройки, которые
вы сейчас видите, сохранять бота не нужно) и в карточке каждого бота.

1. Выберите период: неделя, месяц, 3 месяца, полгода, год или свои даты. Под кнопками
   видно, сколько это свечей. За раз можно проверить до 40 000 свечей: на 1m это
   около 4 недель, на 15m — больше года.
2. Нажмите «Запустить проверку». Свечи загружаются с Binance; повторная проверка на
   том же периоде с другими настройками проходит мгновенно.
3. Что показывает результат:
   - итог закрытых сделок в USDT и в процентах от суммы, которая может понадобиться
     на одну сделку со всеми усреднениями, плюс просадка, комиссии, лучшая и худшая сделка;
   - **почему входил**: сколько свечей выполнялось условие входа и сколько раз бот
     действительно вошёл (в остальное время он уже был в позиции);
   - **почему выходил**: сколько сделок закрылось по тейку, стопу, обратному сигналу
     и сколько это принесло;
   - **график**: свечи, ▲ входы, ● усреднения, ▼ выходы (зелёный — в плюс, красный — в
     минус), индикатор (RSI с порогами или линии EMA) и кривая итога. Наведите на свечу
     со стрелкой — сверху появится цена и причина сделки;
   - **таблица всех сделок**: вход, почему вошёл, усреднения, выход, почему вышел,
     длительность, результат. Нажмите на строку — график покажет эту сделку.

Сигнал считается по закрытой свече, а вход происходит на открытии следующей. Поэтому
RSI в причине входа может немного отличаться от RSI свечи со стрелкой.

Кнопка «График» в карточке бота показывает последние свечи пары с настоящими сделками
этого бота и уровнями открытой позиции: средняя цена, тейк, стоп, следующие усреднения.

Колесо мыши прокручивает страницу; чтобы масштабировать график, кликните по нему.

## Как бот работает

Каждые `POLL_SECONDS` секунд (по умолчанию 15) бот загружает свечи и текущую цену.

- Тейк-профит, стоп-лосс и усреднения проверяются на каждой проверке.
- Сигнал на вход считается один раз на каждую **закрытую** свечу, поэтому он не
  «мигает» внутри свечи.
- Все ордера рыночные. На фьючерсах бот ставит изолированную маржу и заданное плечо.
- Позиция и история сделок хранятся в `data/bot.db`. После перезапуска программы
  запущенные боты продолжают работу с того же места.
- На споте объём продажи округляется вниз до шага лота (для BTC — 0,00001), поэтому
  после продажи на счёте может остаться крошечный остаток монет. Бот помнит его и
  продаёт вместе со следующей сделкой, а его стоимость учитывает в её результате.
- На фьючерсах закрытие позиции не ограничено минимальной суммой ордера Binance, так что
  стоп сработает и для позиции, которая подешевела ниже минимума.
- Каждый ордер сначала записывается в базу со своим ID и только потом уходит на биржу.
  Если ответ не пришёл (таймаут, обрыв связи, программа упала), бот на следующей
  проверке находит ордер на Binance по этому ID и учитывает сделку, а до этого не торгует.
- Кнопка «Остановить» и выключение программы дожидаются конца текущей проверки,
  поэтому не обрывают ордер на полпути.

## Важные ограничения

- **Тейк-профит, усреднения и условия выхода живут внутри программы.** Если компьютер
  выключен или пропал интернет, они не сработают. Стоп-лосс на демо-счёте и реальных
  деньгах дублируется ордером на бирже (см. ниже), в бумажной торговле — нет.
- Боты без стоп-лосса (например, DCA-шаблоны) на бирже ничем не защищены.
- **Одна пара — один бот на один счёт.** На фьючерсах Binance складывает позиции
  по одной паре в одну, а на споте бот продаёт монеты с общего баланса. Не торгуйте эту
  пару вручную с того же счёта.
- Режим позиций на фьючерсах должен быть One-way (так по умолчанию). Hedge mode не поддерживается.
- Если позицию закрыли сами на бирже или её ликвидировало, остановите бота и нажмите
  «Убрать позицию из памяти».
- Комиссия, оплаченная в BNB, в расчёт прибыли не попадает, поэтому итог будет чуть
  лучше реального.
- Проверка на истории приблизительная: порядок движения цены внутри свечи неизвестен,
  проскальзывание и ликвидации не учитываются. Если свеча открылась уже за уровнем
  стопа, тейка или усреднения, ордер считается исполненным по цене открытия.
- Графики рисует библиотека TradingView Lightweight Charts (Apache-2.0), она загружается
  с cdn.jsdelivr.net. Без доступа к нему цифры и таблицы работают, а графика нет.

## Стоп-лосс на бирже

На демо-счёте и реальных деньгах стоп-лосс ставится ещё и ордером на Binance. Он
сработает, даже если программа выключена или пропал интернет. Галочка «Ставить
стоп-лосс ордером на бирже» в настройках бота включена по умолчанию.

- **Фьючерсы:** STOP_MARKET с reduceOnly по маркировочной цене. Такой ордер может только
  закрыть позицию, не откроет обратную и не сработает от случайного прокола последней цены.
- **Спот:** STOP_LOSS_LIMIT — другого стопа спот Binance не даёт. Он продаёт не дешевле
  цены стопа минус 1%. Если при обвале лимит исполнился лишь частично, бот снимает остаток
  и продаёт его по рынку.
- Стоп ставится сразу после входа и переставляется после каждого усреднения: средняя цена
  и объём меняются.
- Перед закрытием по тейку, условию или кнопке бот сначала снимает стоп (на споте он
  блокирует монеты). Если стоп уже успел сработать, второй продажи не будет.
- На каждой проверке бот смотрит, жив ли стоп. Сработал — записывает сделку с настоящей
  комиссией. Сняли вручную — ставит заново. Не удалось поставить — тревога в журнале и в
  Telegram, а стоп работает внутри программы.
- **«Остановить» стоп не снимает:** позиция остаётся защищённой. «Убрать позицию из
  памяти» стоп снимает.
- Стоп и программа следят за одним уровнем, поэтому иногда позицию закроет программа, а
  иногда биржа — результат тот же.

## Уведомления в Telegram

1. В Telegram откройте @BotFather, отправьте `/newbot` и получите токен.
2. Впишите его в `.env`: `TELEGRAM_BOT_TOKEN=…` и перезапустите программу.
3. Напишите своему боту любое сообщение.
4. В панели нажмите «Telegram» → «Проверить». Панель покажет ваш chat_id. Впишите его в
   `.env`: `TELEGRAM_CHAT_ID=…` и снова перезапустите программу.

Приходят входы, усреднения и выходы с причиной и результатом. Отдельно приходят тревоги:
стоп не встал на биржу, биржа не подтвердила ордер, ошибка держится дольше одной
проверки. Запуск и остановка приходят без звука. `TELEGRAM_PAPER=0` отключит сообщения о
бумажных ботах. Отправка идёт в фоне: если Telegram недоступен, торговля этого не замечает.

## Запуск на сервере (VPS)

Подойдёт любой Linux-сервер за 4–6 € в месяц, лучше в Европе (Binance недоступен из
некоторых стран, в том числе из США).

```bash
# на сервере, в папке проекта
cp .env.example .env
nano .env                # задайте PANEL_PASSWORD и ключи
docker compose up -d --build
docker compose logs -f   # посмотреть, что всё запустилось
```

Панель слушает только сам сервер. Чтобы открыть её у себя, сделайте SSH-туннель:

```bash
ssh -L 8000:127.0.0.1:8000 user@адрес-сервера
```

и откройте http://localhost:8000. Так панель не видна из интернета вообще.

Панель отвечает только на адреса localhost и 127.0.0.1 и отклоняет запросы, пришедшие
с других сайтов. Если открываете её по IP сервера или домену, впишите их в `PANEL_HOSTS`.

Без Docker: запускайте `./start.sh --no-browser` через systemd или `tmux`, чтобы программа
работала после выхода из SSH.

## Что где лежит

```
start.sh, start.bat, ValesBot.command   запуск одной командой
valesbot.spec   сборка одного исполняемого файла (PyInstaller)
app/
  launcher.py     запуск: .env при первом старте, выбор порта, открытие браузера
  main.py         веб-панель и API
  engine.py       цикл каждого бота
  trader.py       логика сделки: вход, усреднения, тейк, стоп
  strategy.py     настройки бота, шаблоны, сигналы на вход и выход
  rules.py        конструктор условий: описание индикаторов, проверка, тексты
  indicators.py   расчёт индикаторов
  brokers.py      бумажная торговля и ордера на Binance (через ccxt), стоп на бирже
  notify.py       уведомления в Telegram
  backtest.py     проверка на истории
  static/index.html   интерфейс
```

Свой индикатор добавляется в `app/rules.py` (см. «Конструктор условий») — панель,
бэктест и график подхватят его автоматически.
